API Generators

Open in ChatGPTOpen in ClaudeView in Markdown

LaunchPad’s API generators turn mediator requests into a server. You list the requests an operation host exposes, and the generator writes the endpoints, each of which sends its request through your mediator. Clients are generated the usual way, from what the server describes: its OpenAPI document, its GraphQL schema or its .proto.

The generators work with MediatR, martinothamar/Mediator, ChannelMediator, Immediate.Handlers, Foundatio.Mediator and ZeroAlloc.Mediator. They are incremental source generators: nothing is found by reflection or by scanning assemblies, and the generated Minimal API endpoints are native AOT safe.

This page covers the Minimal API, MVC controller, gRPC and GraphQL (mutations) servers, and generating clients for them.

Packages

Section titled “Packages”

The generators ship in Rocket.Surgery.LaunchPad.Foundation, next to LaunchPad’s other source generators, so a project that references Foundation has them: the attributes ([ApiOperation], [Operation<T>], …), host checks, code fixes, and the generators for Minimal API (*Endpoints), MVC (*Controller), gRPC (*Service) and GraphQL (*Mutations). Reference Foundation from the servers and from contracts that customise their operations.

The attributes are generated into each project that uses them, as internal types, so nothing reaches your runtime dependencies. One generator per transport runs in every project that references Foundation, and each writes code only for the hosts of its kind, using that transport’s library (ASP.NET Core, protobuf-net.Grpc or HotChocolate). Why they share Foundation’s analyzer is recorded in ADR 0004.

Quick start

Section titled “Quick start”

Contracts: plain mediator requests. Nothing is required: XML documentation becomes the OpenAPI summary, [ApiOperation] adds metadata to the operation, and [Creates] marks a response that identifies a new resource.

Server: a static partial class named *Endpoints, one attribute per operation.

Client: generated from the server’s OpenAPI document by the tool of your choice. See Generating clients.

Operation hosts

Section titled “Operation hosts”

An operation host is a top-level partial type. The generator writes complete members into it, with signatures it chooses. A host lists every operation it exposes, so nothing becomes public by accident (ADR-0003).

The transport comes from the host itself; the first rule that matches wins:

The host…Transport
derives from ControllerBaseMVC controller
has [ExtendObjectType(Query)] / (Mutation)GraphQL query / mutation
is named *ControllerMVC controller
is named *Endpoints or *ApiMinimal API
is named *ServicegRPC server
is named *Queries / *MutationsGraphQL

A host that matches nothing, or whose transport’s library isn’t referenced, is LPAD1017. A Minimal API host must be static partial and any other host partial; LPAD1010 has a code fix that adds the modifiers.

Names, groups and routes

Section titled “Names, groups and routes”
  • The operation name comes from the request: GetRocket.Request and GetRocketRequest are both GetRocket. A nested type named only by a verb takes its container’s noun: EditRocket.PatchRequest is PatchRocket. The name is the endpoint name and OpenAPI operation id, the gRPC method and (camelCased) the GraphQL field, so it’s also the method name in generated clients.
  • The group is the host name without its suffix, in kebab-case: RocketsEndpoints and RocketsService are both rockets. Set [OperationHost(Group = "...")] to choose another.
  • The route is RoutePrefix / group / path. The prefix defaults to api. The path is REST style: the verb prefix and the group noun are dropped from the operation name, and {id} comes first when the request has an Id. Tokens get the constraint of their member’s type ({id:guid} for a Guid, or for a strongly typed id whose Value is one); a Route you write is used as written.

ListRocketsGET /api/rockets200
GetRocketGET /api/rockets/{id}200
CreateRocketPOST /api/rockets201

Verbs come from the name’s prefix: Get/Find/List/Search… are GET, Create/Add/New… are POST (201), Edit/Update/Save… are PUT, Patch is PATCH, Delete/Remove/Cancel… are DELETE (204), and anything else is POST. Two operations with the same verb and route are LPAD1008.

Customising an operation

Section titled “Customising an operation”

Named arguments on [Operation<T>] win over [ApiOperation] on the request, which wins over the rules above:

On [Operation<T>]Effect
Route, Verb, NameOverride the path, verb and endpoint name.
Summary, Description, TagsOpenAPI metadata.
Policy, Roles, AuthenticationSchemes, AllowAnonymousAuthorization on the endpoint.
InputBind a transport-specific input type and convert it with its Create() (LPAD1020).
VersionThe API version of the operation, overriding the host’s (see below).

[Creates(typeof(TRequest))] (or [Creates<TRequest>] where generic attributes are available) on a response type makes every operation that returns it answer 201 Created, with a Location header for TRequest’s GET operation, filled from the response’s members (CreateRocket.Response.Id → {id}). The target is looked for on the same host first, then on any other host of the same transport. When no host exposes it, or a route value has no matching member, the operation still answers 201, without a Location, and LPAD1023 says why.

Summaries and descriptions come from, in order: the operation’s Summary/Description, [ApiOperation], and the <summary>/<remarks> of the request type or of the type that contains it (GetRocket for GetRocket.Request). For a request in a referenced project, the base package’s build targets hand that project’s XML documentation file to the generators, so turn on GenerateDocumentationFile there. A contracts package can be added with <AdditionalFiles Include="path/to/Contracts.xml" LaunchPadApiDocumentation="true" />.

API versions

Section titled “API versions”

[OperationHost(Version = "1.0")] gives every operation of the host an API version, and [Operation<T>(Version = "2.0")] overrides it for one operation. The server maps them with Asp.Versioning; clients send the version in the api-version query string, Asp.Versioning’s default reader.

  • Minimal API hosts build one version set from the versions of their operations and map each endpoint to its own version (WithApiVersionSet, MapToApiVersion). Reference Asp.Versioning.Http and call AddApiVersioning().
  • Controller hosts get an [ApiVersion] per version on the class and [MapToApiVersion] on each action. Reference Asp.Versioning.Mvc and call AddApiVersioning().AddMvc().

A request for a version the endpoint isn’t mapped to, or with no version, answers 400 with Asp.Versioning’s problem details. To accept unversioned requests, set AssumeDefaultVersionWhenUnspecified and DefaultApiVersion in AddApiVersioning(options => ...). Without the package for the host’s transport (Asp.Versioning.Http for Minimal API, Asp.Versioning.Mvc for controllers), versions aren’t mapped and LPAD1024 warns. gRPC and GraphQL hosts have no API versions; Version on them is LPAD1021.

MVC controllers

Section titled “MVC controllers”

A partial class named *Controller (or deriving from ControllerBase) gets one action per operation, on the same routes as a Minimal API host would:

  • The generator adds [ApiController], [Route("{RoutePrefix}/{Group}")] and the ControllerBase base only when the host doesn’t declare them. A host’s own [Route] replaces prefix and group ([controller] is the host’s noun), and its hand-written actions, filters and attributes stay as they are.
  • Actions return MVC results, so responses use MVC’s formatters and AddJsonOptions settings, and carry [ProducesResponseType] for ApiExplorer. Binding failures answer 400 through [ApiController].
  • The mediator is resolved inside the action, so the host’s constructor is yours.
  • MVC only discovers public controllers.

gRPC

Section titled “gRPC”

A partial class named *Service becomes a code-first gRPC service with protobuf-net.Grpc. The generator writes its contract too (a [Service] interface, one operation per request), so the contracts project needs no gRPC reference.

  • The service is {package}.{Service}: the group as the package and in PascalCase as the service, so rockets.Rockets and routes such as /rockets.Rockets/GetRocket, whatever the server’s C# namespace.
  • The whole request is the message: route, query and header binding don’t apply.
  • Requests and responses need [DataContract] with ordered [DataMember]s, or [ProtoContract] (LPAD1014). Positional records work: the generated code lets protobuf-net create them without a parameterless constructor.
  • Nested types are named with their container (CreateRocketRequest), so the many X.Request types don’t all become message Request.
  • Messages use protobuf-net’s compatibility level 300: a Guid or decimal travels as a string, a DateTime as google.protobuf.Timestamp and a TimeSpan as google.protobuf.Duration, the types a .proto declares, not protobuf-net’s bcl.proto messages.
  • protobuf-net.Grpc only carries classes. A struct request or response (ZeroAlloc’s requests) goes in a wrapper the generator writes, which protobuf-net replaces by the struct itself on the wire, so its message is the struct’s. A primitive response (bool) travels in a one-field message. Void operations answer google.protobuf.Empty.
  • A null response answers NotFound. Streams are server streaming.
  • GetProto() is generated when the server references protobuf-net.Grpc.Reflection.

GraphQL mutations

Section titled “GraphQL mutations”

A partial class named *Mutations (or with [ExtendObjectType(OperationTypeNames.Mutation)]) gets one HotChocolate mutation per operation, taking the request as its single request argument:

  • Field names are the operation names in camelCase, or [ApiOperation(GraphQLName)]. A field declared on two mutation hosts is LPAD1009.
  • Add{Host}() names nested inputs and responses after their container (CreateRocketRequest, CreateRocketResponse), so the many nested Request types don’t collide; other inputs keep HotChocolate’s …Input names. LaunchPad.HotChocolate’s NestedTypeNameTypeInterceptor leaves those names as they are.
  • A void operation answers Boolean! (true). A stream isn’t a mutation (LPAD1015, skipped).
  • An operation is a mutation unless its verb is GET; one inferred as a query on a mutation host is LPAD1019. Set [ApiOperation(GraphQLOperation = GraphQLOperation.Mutation)] to keep it.
  • Input types work as on HTTP. An input implementing LaunchPad’s IOptionalTracking<TRequest> gets its Create() from another generator, which counts.
  • The summary (or XML documentation) is the field’s description; Policy, Roles and AllowAnonymous become HotChocolate authorization.

Queries aren’t generated. They usually return IQueryable with paging, filtering and projections, which a mediator response can’t; a *Queries host is LPAD1017. Write queries by hand.

Binding and responses

Section titled “Binding and responses”
  • Route tokens bind to the request member of the same name; a token without a member is LPAD1003, an [ApiRoute] member missing from the route is LPAD1004.
  • GET and DELETE take the other members from the query string; complex members there are LPAD1005. POST, PUT and PATCH take the whole request as the JSON body, and route values are applied on top (request with { Id = id } for records).
  • Route, query and header values must be parsable: primitives, enums, Guid, date and time types, or anything with IParsable<T> or a static TryParse (LPAD1007). Strongly typed IDs work when they provide one.
  • [ApiQuery], [ApiHeader], [ApiBody], [ApiService] and [ApiIgnore] on a member override the defaults; ASP.NET Core’s [FromRoute] and friends are honoured too.
ResponseServer answers

IAsyncEnumerable<T>newline-delimited JSON (application/x-ndjson), one item per line, flushed per item

A binding failure answers 400, with a ProblemDetails body when the application calls AddProblemDetails(). Generated endpoints describe their parameters, bodies and responses to ApiExplorer, so OpenAPI documents them like hand-written ones.

Union responses

Section titled “Union responses”

A handler can return a union response, its value case and its error cases, instead of throwing (ADR-0006). A union is a C# 15 union: a union declaration, LaunchPad’s portable [Union] partial struct (see the union types design), or the same shape written by hand. The generators know it by System.Runtime.CompilerServices.UnionAttribute or IUnion. Its case types are the parameter types of its public one-parameter constructors. An error case is known by its name or by [ApiError]; the value case is the first case that is neither, and a union has exactly one.

LaunchPad’s standard problem cases in Rocket.Surgery.LaunchPad.Primitives (NotFound, Invalid, UnprocessableEntity, Unauthorized, Forbidden, Conflict) match the name rules below. A union may list Problem itself as a case: it answers each standard case by its runtime type, and any other problem as 500. A problem’s detail, title, link, instance and properties fill the transport’s error shape (below).

The value case answers like a plain response: 200, 201 with [Creates], 204 for a unit (Unit, ValueTuple), 404 when it or the union (LaunchRocketResult?) is nullable and null. An error case’s status comes from [ApiError] on its type, or else from its name, ignoring an Error, Exception, Problem, Failure or Result ending:

Name starts or ends withHTTPgRPCGraphQL code
NotFound404NotFoundNOT_FOUND
Unauthorized, Unauthenticated401UnauthenticatedUNAUTHENTICATED
Forbidden403PermissionDeniedFORBIDDEN
Conflict409FailedPreconditionCONFLICT
Validation, UnprocessableEntity422InvalidArgumentBAD_USER_INPUT
Invalid400InvalidArgumentBAD_USER_INPUT

[ApiError(statusCode)] sets the HTTP status; its gRPC status and GraphQL code default to the ones for that status. A second case that matches no name and has no [ApiError] is LPAD1028. Each transport carries the case name, so cases that share a status stay distinct:

  • HTTP: ProblemDetails (application/problem+json) with the status, the case name in a case extension and the case’s members as camel-cased extensions; a problem’s detail, title, link (as type) and instance fill those fields and its properties are extensions. Each status is described in OpenAPI as a ProblemDetails response; a schema per case is planned with the OpenAPI transformers (#3149).
  • gRPC: an RpcException with the status, the case name in the case trailer and the case, serialized by protobuf-net, in the case-bin trailer (left out for a case without members). A problem’s detail is the status message and it has no case-bin. A case with members needs [DataContract] or [ProtoContract] (LPAD1014), and GetProto() declares its message.
  • GraphQL: an error whose extensions.code is the code from the table (or [ApiError(GraphQLCode)]), with the case name in extensions.case and the case’s members as extensions. A problem’s detail is the error message and its properties are extensions. The codes follow the convention most GraphQL servers and clients use.

A stream of unions (IAsyncEnumerable<LaunchRocketResult>) streams its value cases and ends with the first error case: over HTTP, as the response’s ProblemDetails when nothing was written yet, otherwise as a last NDJSON line holding the problem; over gRPC, as the RpcException above. GraphQL hosts skip streams (LPAD1015).

NotFoundException and a null response keep answering 404 for handlers that don’t return a union.

Generating clients

Section titled “Generating clients”

The generators don’t write clients. Each server describes itself in a standard format, and any client generator for that format works:

ServerSpecClient generators
Minimal APIOpenAPI: AddOpenApi() and MapOpenApi() (Microsoft.AspNetCore.OpenApi)NSwag, Kiota, OpenAPI Generator, Refitter, …
ControllersOpenAPI, the same waythe same
gRPC.proto: {Host}.GetProto()Grpc.Tools (<Protobuf GrpcServices="Client" />), any protoc plugin
GraphQLSDL: HotChocolate serves it at /graphql?sdlStrawberryShake, graphql-codegen, …

Write the spec at build or in CI, for example from a small console app or test that starts the server with TestServer and saves /openapi/v1.json, /graphql?sdl and GetProto(), then point the client generator at the files. LaunchPad’s own functional tests do that (test/Api/Functional/Clients): NSwag, Grpc.Tools and StrawberryShake clients, generated from the specs on every build.

Things to know:

  • Nested request types. Microsoft.AspNetCore.OpenApi names a schema after the type’s simple name, so GetRocket.Request and CreateRocket.Request would both be Request. Name them with their container:

  • Streams. OpenAPI documents a stream as application/x-ndjson, which most generated clients don’t read: they expect one JSON array. Read the response yourself, one JSON item per line.

  • Struct requests. System.Text.Json builds a struct through its parameterless constructor, so OpenAPI doesn’t mark its positional members required the way it does a record class’s. Add [Required] to keep generated clients non-nullable.

  • StrawberryShake declares a local named request in each generated operation, so a variable named $request doesn’t compile (CS0136). Name the variable something else: mutation CreateRocket($rocket: CreateRocketRequest!) { createRocket(request: $rocket) { id } }.

Mediator profiles

Section titled “Mediator profiles”

The generators find your mediator from the libraries the project references. Exactly one of the built-in profiles must match, or you declare one (LPAD1002):

MediatorRequestsServer dispatches through
MediatRIRequest<T>, IRequest, IStreamRequest<T>ISender
martinothamar/MediatorIRequest<T>, ICommand<T>, IQuery<T>, ICommand and stream variantsISender
ChannelMediatorIRequest<T>, IRequest, IStreamRequest<T>IMediator
Immediate.Handlersanything; the response comes from the [Handler] (a bare ValueTask is void) or [ApiOperation(Response)]IHandler<TRequest, TResponse>
Foundatio.Mediatoroptional IRequest<T>/ICommand<T>/IQuery<T>, or ICommand for void, else [ApiOperation(Response)]IMediator.InvokeAsync

Requests that implement no marker interface (Immediate.Handlers, and optionally Foundatio) name their response with [ApiOperation(Response = typeof(...))]. typeof can’t say “nullable”, so for Immediate.Handlers the server takes the nullability from its [Handler] method when that is next to the request or the host.

Patch operations

Section titled “Patch operations”

A patch operation’s request carries only the changes to another operation’s request: it implements IPropertyTracking<TRequest>, and the property tracking generator gives it an Assigned<T> member for each property of TRequest and an ApplyChanges method. Its handler is generated too. Declare the handler class partial, with the mediator’s handler interface and the services it needs, including the mediator’s sender, and implement GetRequest, which loads the current request:

The generated handle method applies the patch to that request and sends the result through the mediator, so the full request is validated like any other. The handle method’s shape (Task<T> or ValueTask<T>, the cancellation token) comes from the mediator’s handler interface, and the handler interface is written in your source, so a mediator’s own source generator (Mediator, ZeroAlloc.Mediator) still finds the handler. A profile without a sender (Immediate.Handlers) can’t send the patched request (LPAD1025).

Native AOT

Section titled “Native AOT”

Generated Minimal API endpoints don’t rely on the Request Delegate Generator (which can’t see generated code): they parse route, query and header values, read the body and write the result through the application’s JsonTypeInfo. A native AOT application supplies a JsonSerializerContext:

LaunchPad’s nested X.Request types share a simple name, so each [JsonSerializable] entry needs its own TypeInfoPropertyName; without it, SYSLIB1031 silently skips the type. In a project that sets PublishAot, IsAotCompatible, PublishTrimmed or IsTrimmable (or LaunchPadApiRequireJsonContext), LPAD1030 names each body and response type no context in the project or its references declares, or reaches through its properties and collections. See JSON and native AOT. In an AOT application, Configure{Operation} receives an IEndpointConventionBuilder, and endpoint filters don’t apply. test/Api/Aot publishes such a server with PublishAot and checks it with a round trip over HTTP.

Limitations

Section titled “Limitations”
  • The generators don’t configure Asp.Versioning’s reader: versions are read from the api-version query string unless you configure it.
  • With Foundatio, give each request its own handler class: Foundatio’s generator names its wrappers after the message’s simple name, which nested X.Request types share.
