Domain primitives

Open in ChatGPTOpen in ClaudeView in Markdown

A domain primitive is a type that holds a value of a domain concept (an email address, an amount, an order’s ID) and only accepts values its rules allow: there is no instance of it that breaks them. A domain primitive is one of these:

  • a single value: a string, a number or a date, checked by its rules;
  • a strong ID, which identifies an entity, so the IDs of different entities can’t be mixed up;
  • a smart enum, whose values are a fixed set of named members;
  • a value object, which holds several values, validated together.

A primitive kind is a ready-made set of rules, such as email address, currency code or latitude, applied to a domain primitive the application declares.

Rocket.Surgery.LaunchPad.Primitives depends on no other LaunchPad package, and nothing else brings it: an application or library opts in by referencing it, and the LaunchPad SDK never adds it.

The package holds the interfaces the generated code implements and little else. Its analyzer package, Rocket.Surgery.LaunchPad.Primitives.Analyzers, which it depends on, holds the generator, the analyzers and their code fixes. The generator also writes the attributes into the project: they are internal, exist only in source ([Conditional("CodeGeneration")]), and never reach the compiled assembly. A domain primitive in a referenced assembly is recognized by the interface the generator implements: IDomainPrimitive<TSelf, TValue> for one value (a strong ID implements IStrongId<TSelf, TValue>, which extends it), and IValueObject<TSelf> for a value object; both extend IDomainPrimitive<TSelf>.

The attributes, the interfaces and what you use day to day are in the Rocket.Surgery.LaunchPad.Primitives namespace. The rest is in namespaces of its own: .Advanced (PrimitiveBuilder<TPrimitive, TValue>), .Diagnostics (DomainPrimitivesInstrumentation, the meter and activity source), .Descriptions (what the generated Description of each domain primitive tells the integrations) and .Registries (Iso3166Countries and Iso4217Currencies, the codes [CountryCode], [CurrencyCode] and [Money] accept).

The reasons for this design are in ADR 0011.

Declaring a domain primitive

Section titled “Declaring a domain primitive”

A domain primitive is a readonly partial record struct or a sealed partial record (a record class) with exactly one primitive attribute, and any number of rules. A smart enum is the exception: it is a C# 15 closed partial class or a readonly partial record struct, never a record class (see smart enums).

The two record forms behave the same, except for the missing value:

  • A struct has a default that was never validated. IsDefault is true for it, and reading its Value throws. Prefer a struct: it doesn’t allocate.
  • A class has no default instance and no IsDefault of its own (through IDomainPrimitive<TSelf> it is false). A missing value is null, which nullable annotations track, and JSON null reads as a null reference.

The analyzers report a declaration that isn’t partial, a struct that isn’t readonly, a record class that isn’t sealed, a type that isn’t a record, and a smart enum that is a record class or a class that isn’t closed, and their code fixes add what is missing. A fix that changes the form of a smart enum also changes how its members are made, in every part of it: making it a closed class makes new(1) or new Level(1) into new Low_(1), and making it a record struct makes new Low_(1) into new(1). It finds the members and reads each new as the generator does, however a name is spelled: Sample.Level, global::Sample.Level, an alias, or new Level.Low_(1). The generator reports a type with more than one primitive attribute (LPAD2102), and completes nothing for it. It also leaves alone a declaration of the wrong form: a smart enum that is a record class, or a class that isn’t closed and partial, and any other domain primitive declared as a class that isn’t a record.

Every primitive attribute has ErrorCode and ErrorMessage, which replace the code and message of the errors its kind’s own checks report (the format of [Email], the range of [Percentage], the order of a [DateRange]). They don’t replace the length checks a kind brings (the maximum length of [Email], say), the EMPTY of a strong ID, or the currency check of a pinned [Money("USD")].

Rules

Section titled “Rules”

Rules are attributes on the domain primitive. The normalizations change the value before it is checked; the checks reject it.

RuleApplies toWhat it does
[Trim]stringsRemoves white space from both ends.
[TrimStart], [TrimEnd]stringsRemoves white space from the start or the end.
[LowerCase], [UpperCase]stringsChanges the case (invariant culture). A type can’t have both.
[NormalizeWhitespace]stringsCollapses every run of white space into one space.
[Normalize<TNormalizer>]any valueNormalizes with an INormalizer<T>, after every built-in one. Repeatable.
[NotEmpty]stringsRejects an empty or blank value.
[MinLength(n)]stringsAt least n characters.
[MaxLength(n)]stringsAt most n characters.
[Length(min, max)]stringsFrom min to max characters.
[ExactLength(n)]stringsExactly n characters.
[Regex(pattern)]stringsMatches the pattern. Repeatable; the analyzers check the pattern.
a [GeneratedRegex] memberstringsMatches the pattern, which the regular expression generator turns into code. See below.
[PrimitiveRange(min, max)]numbers and datesFrom min to max: numbers for a number, ISO 8601 text for a date or a time. MinExclusive and MaxExclusive leave out the bounds.
[CustomValidator<TValidator>]any valueChecks with an ICustomValidator<T>, after every other rule. Repeatable.

The string rules apply to a string strong ID too, and [PrimitiveRange] to a strong ID of an int or a long. After the built-in normalizations and before any [Normalize<T>], a string is normalized to Unicode form C, and a string that can’t be (an unpaired surrogate) is rejected with INVALID_UNICODE. A string far longer than its maximum length is rejected before it is normalized, so a huge value costs nothing to reject.

The pattern of a primitive kind is a [GeneratedRegex] of PrimitivePatterns (in Rocket.Surgery.LaunchPad.Primitives.Advanced), which the regular expression generator turns into code when Primitives is built. A pattern of your own can be a [GeneratedRegex] too: every static [GeneratedRegex] property, or method without parameters, of a string domain primitive or a string strong ID is a rule, checked after its [Regex] rules, that reports FORMAT with the default message. Its description (and so the pattern of its OpenAPI schema) is its pattern with the options that change what it matches written inline: RegexOptions.IgnoreCase makes ^[a-z]+$ (?i)^[a-z]+$.

You declare the [GeneratedRegex] yourself because the Primitives generator can’t: the regular expression generator is a source generator too, and one source generator doesn’t see what another writes, so a [GeneratedRegex] the Primitives generator wrote would never be implemented. A [Regex] is built once into a static Regex with RegexOptions.CultureInvariant and a one second timeout, and interpreted rather than compiled, as native AOT interprets every pattern built at run time. LPAD2023 suggests a [GeneratedRegex] for a [Regex] that doesn’t set its own ErrorCode or ErrorMessage and comes after every [Regex] that does, and its fix writes it. The patterns of the kinds have the same one second timeout. A match that times out rejects the value.

Every check but [CustomValidator<T>] has ErrorCode and ErrorMessage too; a custom validator returns its own PrimitiveError. A normalizer and a custom validator are static, so nothing is allocated or resolved to run them:

The project’s settings add rules to every string domain primitive, string strong IDs and the string kinds included (see settings): it is trimmed when LaunchPadPrimitivesTrim is true, must not be empty when LaunchPadPrimitivesNotEmpty is true (a [NotEmpty] of its own keeps its error code and message), and is at most LaunchPadPrimitivesMaxLength characters (4096 by default) when neither its rules nor its kind set a maximum length.

Value object kinds

Section titled “Value object kinds”

[Money]decimal Amount, string CurrencyThe currency is an ISO 4217 code; the amount is from Min to Max.[Money("USD")] accepts only that currency; Min, Max

The generator declares the members of these kinds itself. [Money] trims the currency and makes it upper case, and checks it against Iso4217Currencies (CURRENCY); Min and Max set no limit by default. It adds and subtracts only amounts in the same currency, multiplies and divides by a decimal, and compares (<, <=, >, >=) only amounts in the same currency: amounts in two currencies throw InvalidOperationException. [Money("USD")] also gets Create(amount) and TryCreate(amount, ...), which take the amount alone. DateRange and TimeRange have Contains and Overlaps (both ends included); DateRange has Days, the number of days with both ends included, and TimeRange has Duration.

What the generator writes

Section titled “What the generator writes”

Every domain primitive of one value (a string, a number, a date or a strong ID) gets:

  • Value, the value; and for a struct, IsDefault.
  • PrimitiveName, its name in errors and diagnostics, and Description, the constraints of its rules for the integrations.
  • Create(value), which normalizes and checks the value and throws DomainPrimitiveValidationException (or the exception LaunchPadPrimitivesExceptionType names) when the rules reject it, and TryCreate(value, out result, out error), which returns false and the PrimitiveError (a code and a message) instead.
  • Parse and TryParse for strings, spans and UTF-8 (IParsable<TSelf>, ISpanParsable<TSelf>, IUtf8SpanParsable<TSelf>), so route, query and form values bind to it.
  • ToString and TryFormat (IFormattable, ISpanFormattable, IUtf8SpanFormattable).
  • Explicit conversions to and from the value. There are no implicit conversions: a domain primitive is only made by its rules.
  • Equality, and comparison (IComparable<TSelf> and the comparison operators) when the value is comparable.
  • A TypeConverter and a System.Text.Json converter (see JSON).
  • A nested Errors class with a constant for each code it can report, named in Pascal case: Errors.NullInput is "NULL_INPUT".

A smart enum and a value object get less of this; their sections say what.

The codes are these, as they apply, and any ErrorCode a rule or a primitive attribute sets:

CodeReported by
NULL_INPUTa null string
INVALID_UNICODEa string that isn’t valid Unicode
EMPTYan empty or blank string ([NotEmpty], a kind that requires a value), or the empty value of a strong ID
LENGTHthe length rules
FORMAT[Regex], a [GeneratedRegex] member, and the format of a string kind (its pattern, its URL schemes, its ISO list, the IBAN check)
RANGE[PrimitiveRange], the bounds of a kind, a float, double or Half that isn’t finite
SCALE[Rating] with more decimals than its Scale
TEMPORALPastOnly, FutureOnly, and the checks of the date kinds
UNKNOWN_MEMBERa value or a name that isn’t a member of a smart enum
CURRENCYa [Money] currency that isn’t an ISO 4217 code, or not the currency of [Money("USD")]
INVARIANTnothing generated: it is the code for a value object’s own Validate to use

A [DateRange], a [TimeRange] and a [Money] with Min or Max report RANGE too.

Rocket.Surgery.LaunchPad.Primitives also has ToDomainPrimitiveList and ToDomainPrimitiveArray, which create a domain primitive from each value of a sequence, and PrimitiveBuilder<TPrimitive, TValue> (in .Advanced), which adds checks decided at run time.

Operations on [NumericPrimitive<T>] chooses the arithmetic operators, and every result is checked by the rules again:

The arithmetic is checked, so an integer or a decimal that overflows throws OverflowException, and a result the rules reject throws like Create.

Dates

Section titled “Dates”

PastOnly, FutureOnly, [BirthDate] and [ExpirationDate] compare against “now”, read in UTC (today is the UTC date): a value equal to now is in the past, not the future. Create and TryCreate of such a domain primitive have overloads that take where now comes from: a TimeProvider for DateOnly, TimeOnly and DateTimeOffset, and NodaTime’s IClock for the NodaTime types. Without one they use the system clock. The helpers of the date kinds (GetAge() of a [BirthDate], IsExpired() and DaysUntilExpiration() of an [ExpirationDate]) take an optional TimeProvider or IClock the same way, so a test can fix the time. PastOnly and FutureOnly have no meaning for a Duration, Period, Offset or AnnualDate, and setting both rejects every value: LPAD2020 reports either.

Strong IDs

Section titled “Strong IDs”

A strong ID also implements IStrongId<TSelf, TValue>:

  • Create() makes a new ID of a Guid. GuidVersion chooses how: 7 (the default) for Guid.CreateVersion7(), which orders by time, or 4 for Guid.NewGuid(). Only a Guid ID can be created; any other throws NotSupportedException. A GuidVersion other than 4 or 7, or one set on a strong ID that isn’t of a Guid, is LPAD2103.
  • Empty is the empty ID: for a class, one that holds Guid.Empty, 0 or an empty string; for a struct, its default. RejectEmpty (true by default) makes Create(value) reject the empty value (Guid.Empty, 0, or an empty or blank string) with EMPTY.

Smart enums

Section titled “Smart enums”

A smart enum is declared in one of two forms, and the generator completes either. In both, each member has a name and a value, and can carry data of its own (a label, a fee):

  • A C# 15 closed partial class, whose members each have a class of their own. Choose it when code handles each member: a switch expression over the member classes must handle every one of them, so the compiler finds each place a new member has to be handled. Its members can also behave differently from each other.
  • A readonly partial record struct, whose members are values of it. Choose it for a lightweight value type that doesn’t allocate. Code handles each member with the generated Match, Map and Switch, and IsDefault tells its default, which is none of the members, from them. A switch over its members isn’t checked for every member, and its members can’t behave differently: nothing derives from a struct.

A smart enum can’t be a record class (LPAD2003), and the generator leaves one alone.

A closed class

Section titled “A closed class”

closed makes the class abstract and lets only its own assembly derive from it, so the compiler knows every class that does. Each member is an instance of a class of its own, named after the member with an underscore and nested in the smart enum, which the generator writes:

  • A member is a public static readonly field of the smart enum’s type, or a public get-only static property of its type with an initializer, made with new of a class of its own, named after the member with an underscore: Pending = new Pending_(...), or new OrderStatus.Pending_(...). That class doesn’t exist until the generator writes it, nested in the smart enum: public sealed partial class Pending_ : OrderStatus, with an internal constructor. Its arguments are the member’s value first, then the member’s data, in the order the smart enum declares them; named arguments (value:, label:) work too. The member’s name is the name of its field or property. A static property of the smart enum’s type without an initializer (Default => Pending) isn’t a member.
  • The data every member carries are the smart enum’s get-only auto-properties ({ get; }) and readonly instance fields, declared without an initializer. The generator’s private constructor assigns them. A property with a body, an initializer, init or set is not data, nor is a field with an initializer, nor an abstract or virtual property. Every member’s class takes the data in its internal constructor, so a datum’s type must be at least internal: not a private type nested in the smart enum, say. A private (or protected) type of a class the smart enum is nested in works only when the smart enum, or a class between them, is private; a protected smart enum is seen by the classes that derive from its container, which can’t see that type.
  • A member changes behaviour in its own part of its class. Declare the behaviour on the smart enum as virtual (or abstract, which every member’s class must then override), and override it in a partial part of the member’s class, nested in a partial part of the smart enum, as Shipped_ does above. closed can be on any one of the smart enum’s declarations.

Code that handles each member switches over the member classes. The compiler knows them all, so a switch expression that leaves one out is CS8509. That is a warning: make it an error (<WarningsAsErrors>CS8509</WarningsAsErrors>, or TreatWarningsAsErrors) so that adding a member breaks every switch expression that doesn’t handle it. A switch statement isn’t checked.

Besides what every smart enum gets, a closed smart enum gets the class of each member, and the private constructor its internal one calls with the value, the member’s name and the data. Each lookup returns the member itself, the instance its field holds. It has no IsDefault: a class has no default instance, and a missing member is null. It has no Match, Map or Switch either: the switch expression over the member classes does their work.

The generator leaves alone a class smart enum that isn’t closed and partial (LPAD2001 and LPAD2019 report it), and reports the declarations it can’t complete:

  • LPAD2103: a static field or property of the smart enum’s type, with an initializer, that isn’t a member: one that isn’t public, a field that isn’t readonly, or a property with a set. Also a member or a datum named like something the generator writes into the smart enum (Value, Name, All, Description, Errors, PrimitiveName, Create, Parse and the rest), and a datum whose type is less accessible than internal.
  • LPAD2104: a member that isn’t made with new of its own class, the member’s name with an underscore: new(1), a method call, another member (Alias = Pending: an alias is a computed property, Default => Pending), new Shipped_(...) for the member Pending, or a class of that name declared outside the smart enum. The class can be one the application declares a part of, nested in the smart enum, as Shipped_ above.
  • LPAD2105: two members made with the same value, when the value of each is a constant. The value is the argument named value, or else the first argument without a name, compared as a value of the smart enum’s value type: 1 and 1L are the same value of a [SmartEnum<long>].

A record struct

Section titled “A record struct”

A record struct smart enum’s members are its public static readonly fields of its own type, or its public get-only static properties of its own type with an initializer, each made with new(...) (or new Size(...)) through the private constructor the generator writes: the member’s value first, then the member’s data, in the order the smart enum declares them. A member’s name is the name of its field or property. The data are read as for a closed class: the smart enum’s get-only auto-properties and readonly instance fields, declared without an initializer. A smart enum without data makes each member with its value alone, new(1).

A member is made with new, never with another member: public static readonly Size Alias = Small; or public static Size Default { get; } = Small; would be a member of its own, with Small’s value, and break Name, All and FromValue, so the generator reports it (LPAD2103). An alias of a member is a computed property, public static Size Default => Small;, which isn’t a member.

Besides what every smart enum gets, it gets:

  • IsDefault, which is true for its default, the one value that is none of the members. Reading the Value of the default throws, its Name is empty and its data are their own defaults.
  • Match, which takes one function per member and returns what the one for this member returns; Map, the same with functions that are given the member; and Switch, which takes one action per member and runs the one for this member. Each has a parameter per member, named when and the member’s name, so adding a member breaks every call that doesn’t handle it.

It has no member classes, so a member can’t change the smart enum’s behaviour: put what differs from member to member in its data. The generator reports, as for a closed class, LPAD2105 for two members made with the same constant value (the argument named value, or else the first argument without a name), and LPAD2103 for a static field or property of its type, with an initializer, that isn’t a member, for a member that isn’t made with new (an alias of another member), and for a member or a datum named like something the generator writes (IsDefault, Match, Map and Switch too). Its constructor is private, so its data can be of a private type.

The data of a record struct smart enum are fields of the application’s declaration, and its value is a field of the part the generator writes. C# defines no order between the fields of a partial struct’s parts, and reports that as warning CS0282; nothing depends on the layout of a smart enum, so Primitives’ analyzers suppress it (LPADSPR2001) for a struct smart enum.

What every smart enum gets

Section titled “What every smart enum gets”
  • Value, and Name, the name of the member’s field or property.
  • PrimitiveName, and a Description that says it is a smart enum and lists its members’ names in camel case for the integrations.
  • All, every member in declaration order.
  • FromValue and TryFromValue, which find a member by its value, and Create and TryCreate, which do the same and report UNKNOWN_MEMBER (Errors.UnknownMember) when no member has the value. FromName and TryFromName find a member by its name, optionally ignoring case; FromName throws UNKNOWN_MEMBER too.
  • Parse and TryParse (IParsable<TSelf>), which take a name in any case or a value, and ToString (IFormattable too), which is the name.
  • Equality by value (IEquatable<TSelf>, == and !=).
  • An explicit conversion to its value, but none from it: FromValue says what happens when no member has it.
  • A TypeConverter, from and to a name or a value, and a System.Text.Json converter (see JSON).

A smart enum implements only IParsable<TSelf> and IFormattable of the parsing and formatting interfaces; the span and UTF-8 ones (ISpanParsable<TSelf>, ISpanFormattable and the rest) are for the domain primitives of one value.

Value objects

Section titled “Value objects”

A value object’s values are its init properties, and it implements IValueObject<TSelf>. It gets PrimitiveName, a Description (its values, for the integrations), an Errors class, Create(...) and TryCreate(..., out result, out error) with a parameter for each value, and a hook for the checks that involve several of them: implement the static partial void Validate(ref T value, ref PrimitiveError error) it declares, and set error to reject the value. It runs after the checks of the kind. A value object has no parsing, no conversions and no TypeConverter; a member that is itself a domain primitive brings its own rules.

A struct value object’s IsDefault is Equals(default): it has no field of its own to track creation, because a partial struct with fields in more than one part has no defined layout (CS0282). So a struct value object whose values are all their defaults is IsDefault, and JSON writes it as null.

A property with set instead of init is LPAD2008, and one that is an array or a mutable collection is LPAD2018: use an immutable collection.

JSON

Section titled “JSON”

The generator writes a System.Text.Json converter for each domain primitive, which never falls back to reflection (ADR 0007). Reading checks the rules, so a rejected value fails to deserialize.

Domain primitiveJSON
one valuethe value: "someone@example.com", 42, "2026-11-23"
smart enumits member’s name in camel case ("shipped"); read by name in any case, or by value, into the member itself
value objectan object of its values, named by the options’ PropertyNamingPolicy, in camel case when there is none: {"amount":12.5,"currency":"USD"}
a missing value: a null class or a struct’s default, a smart enum’s among themnull, both ways

A domain primitive a value object holds is written and read there as it is on its own: a smart enum as its member’s name, which is what the value object’s OpenAPI schema lists ({"status":"shipped","size":"extraLarge"}), read by name in any case or by value.

A domain primitive of one value and a smart enum can also be the key of a dictionary: the key is the value’s text (ToString) or the member’s name in camel case, parsed back through the rules.

System.Text.Json takes the converter of the type it is given, not of its base type, so each member’s class of a closed smart enum (OrderStatus.Shipped_) carries the smart enum’s converter too: a member is written as its name when it is given as object or as its own class. The value converters of EF Core and the type converters of HotChocolate find a member by its class the same way.

A domain primitive of a NodaTime type reads and writes its value through the JSON options it is given, so it uses the NodaTime converters of Rocket.Surgery.LaunchPad.NodaTime (applied by its NodaTimeSystemTextJsonJoint, or ConfigureNodaTimeForLaunchPad). Primitives doesn’t depend on that package, and LPAD2021 warns when a NodaTime domain primitive is declared where it isn’t referenced.

The System.Text.Json source generator doesn’t see what other generators write, so a JsonSerializerContext in the project that declares a domain primitive can’t see its converter. Declare domain primitives in a library the application references: a context in the application sees the converter in the library’s metadata, and so does the JSON context LaunchPad writes for an executable.

NodaTime

Section titled “NodaTime”

When the project references NodaTime, DatePrimitiveKind has the NodaTime types as well: Instant, OffsetDateTime, ZonedDateTime, LocalDate, LocalTime, LocalDateTime, Duration, Period, AnnualDate, YearMonth and Offset. Without NodaTime those members don’t exist, so a project can’t name a type it can’t compile. The package’s targets define LAUNCHPAD_PRIMITIVES_NODATIME when NodaTime is among the project’s references, and the attributes the generator writes keep those members behind it. [BirthDate], [ExpirationDate], [BusinessDate] and [DateRange] take Kind = DatePrimitiveKind.LocalDate, and [TimeRange] takes LocalTime.

In OpenAPI, GraphQL, EF Core and Dapper

Section titled “In OpenAPI, GraphQL, EF Core and Dapper”

An application that references Primitives itself gets Joints that describe its domain primitives, and those of its references, to the libraries it uses. They are templates: written into the application only when it references the library, so Primitives depends on none of them. They read a registry, LaunchPadPrimitives, that the registry generator fills in at build time with every domain primitive the application declares or references and its rules, so nothing reflects over them. An application whose domain primitives reach it only through a reference gets none of these Joints until it references Primitives too: in its OpenAPI document every domain primitive would be an empty schema, because each is written by its own JSON converter, whose output ASP.NET Core can’t see, and EF Core, HotChocolate and Dapper couldn’t map one. So LaunchPad’s analyzer stops the build of such an application with LPAD2024 when it references one of those libraries.

LibraryWhat a domain primitive becomes
Microsoft.AspNetCore.OpenApithe schema of its value with the constraints of its rules (lengths, pattern, range, format, and the member names of a smart enum), in bodies and in Minimal API and MVC parameters
HotChocolatea scalar: the ID scalar for a strong ID, otherwise the scalar of its value (a value with no HotChocolate scalar, such as a NodaTime type, is left to the application), or one named after the domain primitive (LaunchPadPrimitivesGraphQLRepresentation); a value object is an object type of its values
Entity Framework Corea column of its value, with its maximum length and decimal scale, in every DbContext the application declares or references; a value object ([Money], [DateRange], [TimeRange] among them), struct or class, is a complex property
Dappera parameter and a column of its value

For EF Core the registry generator writes a value converter for each domain primitive of one value, and LaunchPadPrimitivesEntityFrameworkJoint configures every DbContext the application declares or references: it replaces the context’s IValueConverterSelector, so a domain primitive is a property of its value wherever it appears, and adds conventions that map every value object as a complex property and give a key that is a strong ID of a Guid a value generator, which calls its Create() when the entity is added. For Dapper, when the application references it, the registry generator writes a type handler for each domain primitive of one value it can see and a module initializer that registers them, so there is nothing to call. Two assemblies that register a handler for the same type register the same handler. Dapper looks a handler up by a value’s runtime type when a parameter’s type isn’t known, as with DynamicParameters.Add, and a member of a closed smart enum is an instance of its own class, so the smart enum’s handler is registered for each member’s class (OrderStatus.Shipped_) too. Dapper doesn’t run a type handler on the items of a list parameter (where Status in @statuses), for any type, so pass their values there (statuses.Select(z => z.Value)).

Metrics and traces

Section titled “Metrics and traces”

The generated Create and TryCreate record three counters on the Rocket.Surgery.LaunchPad.Primitives meter, each with a primitive_type tag (and error_type for a failure):

CounterCounts
domain_primitive.creationdomain primitives created
domain_primitive.validation.successvalues a domain primitive accepted
domain_primitive.validation.failurevalues a domain primitive rejected

A rejected value also adds a domain_primitive.validation.failure event to the current activity when the Rocket.Surgery.LaunchPad.Primitives activity source has a listener. Nothing is recorded until something listens. The meter and the activity source are DomainPrimitivesInstrumentation.Meter and .ActivitySource, in Rocket.Surgery.LaunchPad.Primitives.Diagnostics. When the application references OpenTelemetry the registry generator writes AddLaunchPadPrimitivesInstrumentation() for MeterProviderBuilder and TracerProviderBuilder, and the LaunchPadPrimitivesInstrumentationJoint template calls it, so the OpenTelemetry LaunchPad sets up includes domain primitives with no code.

Analyzers

Section titled “Analyzers”

LPAD2001 to LPAD2024 are analyzers. LPAD2024 is LaunchPad’s own analyzer, which every LaunchPad application runs, as Primitives’ analyzers don’t run in an application that only gets Primitives through a library. LPAD2101 to LPAD2105 are reported by the generator itself: they are declarations it has to refuse to complete as written, so it is the generator that finds them. LPADSPR2001 isn’t a diagnostic: it suppresses CS0282 on a record struct smart enum that carries data (see a record struct).
